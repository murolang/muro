Muro · for programmers

Do the call before you copy it

When the value about to be copied is still a call, performing that call first saves one substitution per extra use. Nest the copier, and the same choice saves almost nothing, because the copying itself is the long part.

Proved, on three programs

8 uses: 10 steps instead of 17. The save is k − 1.

Counted, on nested copies

16 nested copies: 262,142 steps. Preferring the argument saves 8.

The score

One substitution, then stop at the head

A step writes the argument in place of the parameter:

(λ (x) → body) argument    →    body, with argument for x

Count those steps until the term in front of us is no longer a call we can step into. That count is the whole score. Written as a stream, each step is 0, and the stopped head is 1 forever. Fewer steps means the 1s start sooner.

The checker’s reducer is left as it is. This is a second way of choosing the next call.

The only choice

The call in front of you, or the call inside its argument

Spine

Perform (λ (+ f) → …) applied to the whole argument. If that argument is still a call, the call is copied into every use.

Argument

Perform (λ h → h) applied to (λ g → g) first. What gets copied is the function that call returns.

(λ (+ f) → f (f done))   ((λ h → h) (λ g → g))

+ means f may occur more than once, so the value is copied. There is no third kind of step. A call that is not already in the term is never invented.

examples/lam_uses.muro

The same call, used 2, 4, and 8 times

def redex := (λ h → h) (λ g → g)

def copy2 :=
  (λ (+ f) → f (f (λ n → n))) redex

redex returns its argument unchanged, so performing it yields λ g → g. Until then, f receives the whole call. copy4 and copy8 are this definition with four and eight uses. In the file, f has the type of redex and the result is Π (n : Nat) → Nat.

For k uses the spine pays two steps per copy, because each copy is still a call. Doing the call once, up front, leaves a function, and each use is then one step.

Counted · a longer episode

Nesting the copier doubles the steps

def dup := λ (+ f) → λ n → f (f n)
def bad := (λ h → h) (λ n → n)

depth d  :=  dup (dup (… (dup bad))) 0

dup places two uses of f on the spine. Wrapping another dup around it doubles those uses. The head stops at 0. Spine steps are exactly 4·2^d − 2.

Counted · where the steps go

The copying is the long part

Depth 1

bad is the argument of dup. Doing it first saves one step. Same shape as copy2.

Depth 2 and on

The argument of the outer dup is another dup. That step copies bad before bad is a function.

Conclusion

What is worth repeating

  1. 1The score is the number of substitutions until the head stops. On two, four, and eight uses of one pending call, doing that call first takes 4, 6, and 10. The spine takes 5, 9, and 17. The save is k − 1.
  2. 2That choice is proved for every term reachable from those programs, together with the one-use, discarding, and length terms. The proof is a coinductive homomorphism: the preferred action’s rewards dominate. The preferred action is the argument only at the three copy programs, and the spine everywhere else.
  3. 3A boolean test with the same idea — parameter used more than once, argument contains a call — is one step longer on length (4 against 3). The proof does not follow that test.
  4. 4Nesting dup makes the episode 4·2^d − 2. At depth 16 that is 262,142 steps, and preferring the argument saves 8. The same tower on a function that is already a λ takes 196,606. The long part is the copying.

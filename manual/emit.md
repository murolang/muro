# Emit

In brief: emit keeps `run`. `run internal` is `defp`. Spec and evidence are omitted. Erased Π-arguments are dropped from the generated arity. A non-run fragment that somehow remains becomes `raise "erased term"`. `--backend c` writes C for closed `Nat`, data, and `run` streams. An exported run of `Nat` arguments and a `Nat` result is also a NIF. `--backend rust` writes the same closed run as Rust. `--backend asm` writes a Cortex-M0 `Nat` run.

## From a file

```
iex -S mix
```

```
{:ok, src} = Muro.emit_file("examples/half_ok.muro", Foo)
IO.puts(src)
```

`Muro.emit_file/2` parses, checks (with the prelude in scope), then emits. If the book does not check, you get the error and no module. A prelude `run` the file calls is emitted as `defp`. One the file does not call is left out. The file's own `run` definitions are unchanged.

The generated file starts with:

```
defmodule Foo do
  # Generated by Muro. Evidence never becomes a run.
```

## C

`--backend` chooses the emitter. The default is Elixir, the same text as `Muro.emit_file/3`.

```
mix muro.emit path.muro
mix muro.emit path.muro --backend elixir
mix muro.emit path.muro --backend c
mix muro.emit path.muro --backend rust
mix muro.emit path.muro --backend asm
```

`--backend c` writes `<name>.h` and `<name>.c` next to the file and prints those paths. It emits `run` and `run internal` only. `run internal` is `static`. Erased arguments are dropped. `Nat` is a tagged struct (`0` is zero, `1` is `suc`) with constructors `muro_zero` and `muro_suc`. `Unit` and user `data`, indexed data included, are a tag plus fields. `match` is a `switch`. A constructor with no fields is one static object, the way `tt` is `muro_tt_obj`, and its function returns that address. A constructor with fields allocates through `MURO_ALLOC`. A name that is a C keyword through C23, a typedef from `<stdint.h>`, or a common function from the C library and POSIX (`true`, `read`, `malloc`) is prefixed with `muro_`. Any other name is emitted as spelled. A definition whose spelling is already taken, by an earlier definition or by a constructor function, gains a numeric suffix (`foo_bar_2`).

A `run` stream is a struct: the seed, an environment for values the step closes over, and a function pointer for the step. `unfold n (λ k → (k, suc k))` is `muro_stream_new` of `n` and that step. `uncons` calls the step and returns the head together with a new struct for the tail. The original seed stays in place, as `Enum.take` plus `Stream.drop` does on the Elixir backend. `examples/zeros.muro` and `examples/nats.muro` are the drivers. `Always` and `~` are evidence, so they are omitted. A lambda applied on the spot is a local: the argument is evaluated once and the body uses it. An unapplied lambda, and a call of a local function, are refused (`c:lambda`).

A run whose type or body mentions `I64`, `F32`, or `Tensor` is refused (`c:machine`) and still emits on the Elixir backend. A raw `ν`, `Always`, or `~` inside a `run` is refused (`c:stream`).

The header is shaped like this:

```
/* generated by muro — do not edit */
#ifndef MURO_HALF_OK_H
#define MURO_HALF_OK_H
#include <stdint.h>
#ifndef MURO_ALLOC
#define MURO_ALLOC(n) malloc(n)
#endif
typedef struct muro_nat muro_nat;
struct muro_nat { uint8_t tag; muro_nat *suc; }; /* 0 = zero, 1 = suc */
muro_nat *half(muro_nat *n);
#endif
```

`MURO_ALLOC` is `malloc` unless you define it before the generated file is compiled. Every allocating constructor calls it, and so do `muro_nat_new`, `muro_mk_pair`, and a stream's environment. A fieldless constructor is a static object and does not. The pointer a function returns points into that storage. Read or copy it, then set the cursor back to the start. The next call reuses the block. The static objects stay where they are.

```
#define MURO_ALLOC(n) arena_alloc(n)
```

```
muro_nat *n = two();
/* copy what you need from n */
arena_at = 0;
```

## A Nat run is a NIF

An exported run whose live arguments and result are `Nat` is a NIF entry. `--backend c` writes `<stem>_nif.h`, `<stem>_nif.c`, `<stem>.mk`, and `<stem>.ex` beside the C, and `elixir_make` runs that makefile. The library is `priv/<stem>.so`. The module is the camelized stem (`half_ok.muro` is `HalfOk`). `HalfOk.half(4)` is the integer `2`, and `HalfOk.plus(2, 3)` is `5`.

The entry builds the tagged struct and reads it back. An argument that is not a non-negative integer fitting in 64 bits is a bad argument, and so is a result that does not fit. Allocation goes through `MURO_ALLOC`, defined as one block for the call. The call copies the integer out and resets the block, so the next call reuses it. Two calls do not share the cursor.

`run internal` stays `static` and is not an entry. A run whose argument or result is not `Nat` stays in the C file and is not an entry. A file with no Nat entry writes the `.h` and the `.c` only. A definition that spells `muro_nif_alloc` takes the `muro_` prefix, as the other runtime names do. `cc` translates the C. The proof stops at the run image.

## Rust

`--backend rust` writes `<name>.rs` next to the file and prints that path. It prints the same closed run as the C backend. `run internal` is a private function. `Nat` is `Zero` or `Suc`. An atom is one variant of a closed enum. A stream is a seed and a step. `half(4)` is `2` and `plus(2, 3)` is `5`, the same integers the Nat NIF returns. A term the C backend refuses is refused here, with the same reason.

`rustc` translates this text. `cc` translates the C. CompCert is the high-assurance C translator. Neither is the proof. The proof stops at the run image.

## Cortex-M

`--backend asm` writes `<name>.s` next to the file and prints that path. The text is GNU assembler, Thumb, for Cortex-M0. It prints a `Nat` run. `half(4)` is `2` and `plus(2, 3)` is `5`, the same integers the Nat NIF returns. `run internal` is a label the file can call. It is not exported.

The assembler translates this text. The proof stops at the run image.

## Visibility

| Tag | Elixir |
| --- | --- |
| `run` | `def` |
| `run internal` | `defp` |
| `spec` | omitted |
| `evidence` | omitted |
| `data` | omitted as a type; constructors appear only as runtime tags inside run terms |

`examples/internal_ok.muro`: `step` → `defp step`; `inc` → `def inc` calling `step`.

## How values look

| Muro | Elixir |
| --- | --- |
| `0` | `0` |
| `suc(n)` | `{:suc, n}` |
| `tt` | `:tt` |
| 0-argument ctor (`nil`, `nothing`, `leaf`) | atom (`:nil`, `:nothing`, `:leaf`) |
| n-argument ctor | `{:ctor, args…}` |
| `left n` / `right t` | `{:left, n}` / `{:right, t}` |
| `(a, b)` | `{a, b}` |
| `let (a, b) = e in t`, `fst`, `snd` | `({a, b} = e; t)` |
| `run` Stream | `Stream.unfold/2` |
| `addi` / `addt` / `packI` | `Nx.add` / `Nx.stack` / `Nx.tensor` |

`rewrite` emits as its body. `refl` would be `:refl` if it ever appeared in run; it should not.

## Failing functions

A `run` function that can fail returns a sum, and its constructors are the Elixir tags. Nothing in the kernel knows the `{:ok, _}` / `{:error, _}` convention; the constructor names do the work (`examples/result.muro`):

```
data Result (E : Type) (A : Type) : Type where
  ok    : A → Result E A
  error : E → Result E A

def pred : run Π (n : Nat) → Result Unit Nat :=
  λ (n : Nat) →
    match n motive (λ _ → Result Unit Nat)
      | 0 => error tt
      | suc p => ok p
```

emits `def pred(x0)` returning `{:error, :tt}` or `{:ok, x1}`. A caller that wants a raising variant writes it in Elixir over the emitted function; emit never raises except for `Empty`.

## Erased arguments

Erased binders are not parameters of the Elixir function.

```
def length : run Π (- A : Type) → Π (xs : List A) → Nat
```

becomes something like `def length(xs)`. The type argument is gone. In Muro you still write `length Nat ones2` (or `length A as` in a recursive call). The checker sees `A`. Emit does not.

A run definition with the name and live arity of a `Kernel` function or macro (`length/1`, `max/2`, `min/2`, `div/2`) is excluded from the module's `import Kernel`, so the call means the definition: `import Kernel, except: [max: 2]`.

`-` and `'` in a name become `_`. An Elixir reserved word (`and`, `or`, `nil`, `fn`, and the rest of that list) is prefixed with `muro_`. Two source names that spell the same way stay two functions: the later one takes the suffix, so `foo-bar` is `foo_bar` and `foo_bar` is `foo_bar_2`, and a call uses the name of the definition it names.

## Functions as values

A `run` definition becomes an Elixir function with one parameter per live (non-erased) argument, and a function value is a curried closure: a variable applied to two arguments is `f.(a).(b)`, and `λ (x : A) → t` is `fn x -> t end`. A reference to a definition is emitted by how many arguments it is given (`examples/higher_order.muro`):

- As many as its type has Πs: a direct call, `plus(a, b)`.
- Fewer: a curried closure over the rest. `tabulate ident` passes `fn y -> ident(y) end`; `map (plus 2) xs` passes `plus` with `2` bound once and the second argument open. An erased argument is dropped here too, so `length Nat` is a one-argument closure.
- More: the call, then `.()` for each extra argument, since the result is a function value.

A body with fewer λs than its type has Πs is applied to the binders it does not name: `def adder : run Π (n : Nat) → Π (m : Nat) → Nat := plus` emits `def adder(x0, x1)` calling `plus(x0, x1)`.

The C backend has no closures. An unapplied lambda, a definition passed as a value, and a call of a local function are refused there (`c:lambda`).

## What emit is not

It does not type raw Elixir. It does not emit spec or evidence. It does not turn a Stream that is only evidence into `Stream`. It does not use `Nx.Defn`.

If you want a book in the test suite, parse/check/emit it from `test/muro_check_test.exs`. The canonical book `Muro.Example.book/0` must stay in sync with `examples/half_ok.muro` and `agda/Muro/Example.agda`.

# Changelog

## 0.3.0

All definitions can show the grades the checker recorded. `?view=all&grades=on` fades a definition whose quantities are erased, and leaves a definition that still computes at full opacity. A binder with no grade is left as it was. The legend names runtime and erased, and names `%1` or reuse when a binder carries that quantity. The quantities are the ones `Muro.Grade` stored on the checked book.

Synthesis, at `?view=synth`, draws the state graph of an environment: the constructors of `State`, and the steps the book writes between them. A report from `mix muro.synth --json`, opened with `?trace=`, shows the version-space sizes, the surviving predicate, and whether the run was certified. The carriers named in `cex` are lit on the last round. A state is ranked when that report is certified, and unsettled otherwise. A report may also carry `rounds` and `states`. `rounds` gives each round its own size and its own carriers. `states` names each state `ranked` or `unsettled`, and the certificate when the report has one. Those two keys are the hook a later search can fill. This version does not record a counterexample on each round inside the search. Opening the view does not run a search.

Install it by adding `{:muro_visor, "~> 0.3.0"}` to a Mix project. A published package depends on `muro ~> 0.20.12`. A checkout builds against the repository. It does not emit code and it does not change the wall.

## 0.2.1

Muro code on the page is coloured by `Muro.MakeupLexer`. Session words, types, names, numerals, and operators each have their own colour, including `≤`, `→`, and `⊢`. A break in a spec is a space in `Muro.Session.show_proto/1`, so the tokens do not change. The side column starts at 520px and drags wider or narrower. That width is remembered in the browser. Selecting a node, an edge, or a configuration shows the whole definition, from the bytes the parser consumed, with the file's line numbers and the selected column marked. A definition longer than forty lines folds the rest behind "show more". OTP and FSM signatures and clauses are coloured as Elixir. Rust clauses are coloured when a Rust lexer is present. C and Zig stay plain. `?theme=dark`, or a dark colour scheme, draws the same page on a dark ground. The server-rendered page is light until that choice.

Install it by adding `{:muro_visor, "~> 0.2.1"}` to a Mix project. A published package depends on `muro ~> 0.20.12`. A checkout builds against the repository. It does not emit code and it does not change the wall.

## 0.2.0

The page opens on the meetings in the book. They are grouped under the base session, in source order. A row names the meeting, the two conforms, the base session, the step count, and a refinement such as `{d ≤ w}` when the session carries one. Choosing a meeting patches `?meet=` onto the URL, so `http://127.0.0.1:4017/?meet=wire` opens that meeting. The focused view draws the configuration graph the checker recorded as a sequence: two lanes, one per conform, and one row per step, labelled with the value or type sent and the choice branch for `choose` and `offer`. A halted state is a terminal row (`done`, `stop`, or `end`). Step numbers are one colour. An evidence judgement such as `w ⊢ d ≤ w` is a pill beside the arrow, clear of the value label. A context panel shows the session, its dual, the two conforms and their source locations, and a checked badge. The backend switch redraws the OTP, FSM, C, Rust, or Zig outline while that meeting stays open. All definitions, at `?view=all`, is one cluster per base session: the spec and its configurations, the dual, the conforms typed by either, and the meetings over them. A definition that belongs to no session, such as `run kept`, sits in a small other cluster. Each cluster is a light framed region titled with the session name, or other. Boxes stacked in one column share that column's width. A count is a pill on its step edge, off the stroke and clear of the boxes. A meet edge and a dual edge keep a visible run, and the dual is dashed. A conform has one step edge, with a count when more than one step uses it, and a meeting has two meet edges. Meet, step, and dual are drawn in different styles, and the legend shows a sample of each line. Fit is the default. It scales the graph to the pane, and when that would draw a label below 11px it keeps the readable scale and the pane scrolls. Clicking a meeting opens `?meet=`.

Install it by adding `{:muro_visor, "~> 0.2.0"}` to a Mix project. A published package depends on `muro ~> 0.20.7`. A checkout builds against the repository. It does not emit code and it does not change the wall.

## 0.1.0

`mix muro.ui path.muro` opens one checked book on port 4017. It prints the URL of the address it binds and opens it: `http://127.0.0.1:4017/` for IPv4 loopback, `http://[::1]:4017/` for an IPv6 address, and `http://localhost:4017/` for a hostname. The page connects over `/live`. Nodes sit in ranks along use edges, and each edge has its own path, including a loop when a definition uses itself. A session is a compound node. Each meeting lays out its configurations inside that box, with the transitions the checker recorded drawn and labelled. The graph pane scrolls and zooms. Detail and Outline sit beside it. The outline's names, signatures, layouts, and clauses are separate sections. A backend switch redraws the OTP, FSM, C, Rust, or Zig outline without checking the book again. C, Rust, and Zig layouts include each data type's constructor tags and fields. A click or a key selects a node, an edge, or a configuration and shows the source file, line, and column. An edge also shows the out-of-order refusal, naming the process and the protocol, and a use that is not a step says there is no refusal. A meeting that fails to check is that error, with no configurations.

Install it by adding `{:muro_visor, "~> 0.1.0"}` to a Mix project. A published package depends on `muro ~> 0.20.7`. A checkout builds against the repository. It does not emit code and it does not change the wall.
